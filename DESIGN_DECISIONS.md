# Обоснование дизайн-решений в проекте Doorana

## Структура проекта

### Разделение на сервисы
Проект разделен на отдельные сервисы (Renderer, Camera, Map, CollisionService, SpriteManager), что обеспечивает модульность и соблюдение принципа единственной ответственности. Это упрощает поддержку кода и позволяет тестировать компоненты изолированно.

## Алгоритмы рендеринга

### Выбор рейкастинга вместо полноценного 3D-рендеринга
Рейкастинг был выбран как оптимальный способ создания псевдо-3D окружения, поскольку:
1. Он проще в реализации, чем полный 3D-рендеринг
2. Хорошо подходит для игр в стиле DOOM с ограниченными возможностями движения (без возможности смотреть вверх/вниз)
3. Обеспечивает высокую производительность даже на слабых устройствах

### Использование Z-буфера для спрайтов
Z-буфер используется для корректного отображения спрайтов:
1. Для каждого столбца экрана сохраняется расстояние до ближайшей стены
2. При рендеринге спрайтов проверяется, не закрыты ли они стеной
Это решение позволяет избежать сложных геометрических вычислений для определения видимости спрайтов.

### Оптимизация расчета углов для спрайтов
Расчет углов для определения положения спрайтов на экране использует Math.atan2, что обеспечивает:
1. Корректный учет знаков координат (в каком квадранте находится спрайт)
2. Избегание деления на ноль
3. Получение результата в диапазоне [-π, π], что удобно для последующих вычислений

### Сортировка спрайтов от дальних к ближним
Спрайты сортируются по расстоянию от камеры (от дальних к ближним) перед рендерингом, что обеспечивает корректное перекрытие спрайтов без необходимости сложных вычислений с полигонами.

## Визуальные эффекты

### Затенение объектов в зависимости от расстояния
Реализация эффекта тумана (уменьшение яркости удаленных объектов) выполнена путем:
1. Линейного уменьшения яркости цвета в зависимости от расстояния
2. Установки минимального уровня яркости (0.1), чтобы объекты не становились полностью черными

Это решение улучшает восприятие глубины и создает более реалистичное ощущение пространства.

### Псевдо-текстурирование стен
Вместо использования изображений для текстур разработан алгоритм псевдо-текстурирования, который:
1. Определяет сторону удара луча (север, юг, запад, восток)
2. Применяет разные оттенки в зависимости от стороны
3. Создает эффект кирпичной кладки с помощью изменения цвета в зависимости от позиции

Это решение позволяет создать визуально разнообразную среду без использования внешних ресурсов.

### Градиентный пол и потолок
Градиентный эффект для пола и потолка реализован путем рисования нескольких прямоугольников с постепенно изменяющейся яркостью, что:
1. Создает иллюзию глубины
2. Улучшает восприятие пространства
3. Обходит ограничения API, не поддерживающего градиенты напрямую

## Обработка коллизий

### Скольжение вдоль стен
Вместо простой остановки при столкновении со стеной реализовано скольжение, которое:
1. Улучшает игровой опыт, делая управление более плавным
2. Позволяет игроку "скользить" вдоль стены при диагональном движении
3. Реализовано через попытку движения по отдельным осям X и Z

### Проверка коллизий в нескольких точках
Коллизии проверяются не только в центре игрока, но и по периметру, что:
1. Предотвращает "застревание" в стенах
2. Обеспечивает более реалистичное ощущение перемещения персонажа с физическими размерами
3. Повышает точность определения столкновений
